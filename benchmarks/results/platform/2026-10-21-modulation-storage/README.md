# Strategy-specific modulation storage — CUDA validation, 2026-10-21

Implementation: AOS `9a51f458`. Copper modes: `47e305f`. Launcher selection:
`dad7605`. Baseline AOS: `074f15eb`. The tested uncommitted source was then
committed without numerical source changes; exact harness/environment hashes,
source status and archive digests are retained in `provenance.json` and raw TOML.

## Change and accuracy boundary

Shifted-mask Pyramid propagation now owns compact backend coordinates and
quadrature offsets, with fixed-size host weights. It retains no dense pupil
phase cube. Its existing rate kernels, mask factors, FFT batching, physical
sampling and quadrature are unchanged. Modulation-camera diagnostics evaluate
pupil tilts directly into the existing backend propagation field. Pupil-tilt
and Bi-O-edge paths retain their dense backend phases, generated by a backend
kernel from small CPU-prepared coordinate/offset arrays; there is no dense host
phase temporary or phase-cube upload. CPU preparation fills its destination
directly.

The WFS circular update operation updates diagnostic offsets and rebuilds masks
in place between frames, preserving capture bindings. Updating only compact
modulation is rejected, since that would leave shifted masks stale. This is
synchronous control, not waveform evaluation inside the captured graph.

This is an implementation/storage optimization. Selecting a different numerical
mode changes sampling and requires matching calibration.

## Numerical and capture validation

- **Exact before/after parity** at 480/32 and 240/96 for all 13 probe detector
  rates, 1432-component slope vectors, all 277 central-difference interaction
  columns, 32 evolving atmospheric rate/frame captures, and their stream
  counterparts. Every archived array checksum and byte-identical comparison
  was checked. There are no changed photon, slope or calibration values in
  these shifted-mask results.
- Captured reset/replay was exact. Stream/capture relative rate differences
  were about 1.1 × 10⁻⁷ in both revisions, unchanged by this work. Noisy
  stream/capture frames at 240/96 also differed (maximum 1.024, relative L2
  8.38 × 10⁻⁵), identically before and after. Byte-identical cross-revision
  replay does not imply bitwise stream/capture equivalence.
- **629 focused CUDA checks passed**: Float32/64, CPU/CUDA, circular origin,
  no modulation, sampled/zero weights, nonuniform pupils, diagnostics versus
  dense pupil tilts, separable/full masks, update rejection and stable buffers.
  One capture was replayed after radius changes, disable and re-enable for both
  mask representations. Replay host-allocation checks were zero.
- **1061 CPU WFS checks passed** on the committed source: `wfs-common` and
  `wfs-pyramid-bi-o-edge`.
- Dense phase generation was compared against CPU preparation for odd/even
  pupils and all three policies. GPU trigonometric/fused arithmetic differs
  slightly from host arithmetic and satisfies the package's existing
  `rtol=8eps(T), atol=8eps(T)` phase comparison, not bitwise equality.
  Maximum recorded phase absolute differences: Float32 9.92018954e-07; Float64 1.84777937e-15.

Earlier validation attempts are retained: the initial absolute-only phase check
was stricter than the package's combined tolerance; uploading fixed-size host
weights required an explicit temporary ordinary array at the cold copy boundary.
Both were corrected before the final complete runs. No scalar GPU indexing is
permitted in the passing validation.

## Steady-state performance

One fresh process per revision, 32 warmups, 128 unpaced completed frames per
mode; 16 allocation observations per captured workload. Host elapsed time
includes prepared graph completion. The noisy atmosphere evolves at the
configured model cadence; timing excludes HIL staging and RTC/transport.

| Workload | Baseline median ms | Revised median ms |
|---|---:|---:|
| n480-m32 | 2.626219 | 2.626495 |
| n240-m96 | 1.897263 | 1.896713 |

Captured host allocations were zero throughout both revisions. Frame timing is
essentially unchanged; no runtime speedup is claimed. The large improvement is
retained memory and cold preparation. Full calibration/stream distributions,
128 raw timings per workload, p95 and observed maxima are in the raw TOMLs.
This shared-host, uncontrolled-clock single-pair comparison is not a regression
confidence interval or worst-case latency bound. Profiles from the prior
implementation study remain relevant because rate kernels did not change.

## Explicit Copper numerical modes

Both public captured production/calibration constructors completed validation
for every mode, with actual sampling, fixed boundary shapes and compact GPU
ownership checked. Calibration consumed changed OPD and reproduced flat OPD;
production's seeded atmosphere evolved and replayed exactly after reset. All
96 warmed HIL-service host-allocation observations were zero.

| Mode | Pupil / points | Median completed production HIL service |
|---|---|---:|
| default | 480 / 32 | 2.653 ms |
| fast | 240 / 96 | 1.922 ms |
| accurate | 1440 / 256 | 238.142 ms |

Mode is independent of DM profile, target and stream/captured execution. The
existing default is unchanged. The finer numerical reference costs much more;
its name does not qualify the shifted-mask approximation or provisional
instrument physics against an independent oracle. The existing atmospheric
convergence study motivates fast mode within its tested finite-screen,
noiseless control envelope; operational noisy closed-loop accuracy remains
unqualified. Classic and GPI2 did not receive unvalidated presets.

The scenario launcher accepts Copper `plant.mode`. CPU mode selection passed
6 checks; launcher mocks passed 18 execution checks and 8 mode checks.
Application registered dependency pins are unchanged: deployment of compact
storage requires the corresponding AOS release update. Validation used isolated
source environments and did not contact RTC services or modify application
source overrides.
