## Recommendation

Keep the AOS plant executor and instrument-owned mappings. Borrow JFG's **explicit capture qualification, public boundary metadata, and failure-lifecycle discipline**. These address concrete seams in the current models. A declaration macro, conditional sample execution, asynchronous input joins, and per-node candidate-state commitment have much weaker justification here.

None of this inspection establishes a missing requirement that currently prevents the default stream-based instrument workflows from functioning. It establishes two concrete capability/API gaps, a diagnostic limitation, and one failure-safety question that needs a discriminating test.

## Node API improvements to defer or limit

**Public stateful capture hooks are a legitimate extension improvement, but not the first GPI2 task.** AOS's own atmosphere and detector use specialized capture enqueue/preflight/completion hooks (`AOS/src/algorithm_graphs/native_nodes.jl:415`, `:2517`), while `api.jl:50` marks only the ordinary enqueue/reset/capability surface public. FGA documents `preflight`, `enqueue!`, and `complete!` explicitly (`FGA/src/capture.jl:188`). Stabilize equivalent AOS lifecycle documentation when an external stateful plant node needs it. Preserve AOS's separation of scientific state, RNG, scratch, products, and exact bindings. GPI2's current routing/layout nodes have no persistent scientific history, and Classic/Copper use native AOS nodes, so no current adapter needs new stateful hooks merely to exist.

**Prefer conformance checks to a new macro now.** FGA's `@algorithm` generates configuration, metadata, checked execution, preparation, and lifecycle wiring (`FGA/src/declarations/algorithm_macro.jl:1`); it also checks Workspace lifecycle applicability (`declarations/prepared.jl:102`). AOS's `_prepare_exact_node` accepts the prepared owner without equivalent adapter-lifecycle validation (`preparation.jl:927`). This is an authoring opportunity, not a demonstrated defect in the current GPI2 adapters: both already define step/reset. Because AOS has catch-all error fallbacks, a naive `applicable(step_graph_node!, owner)` check would always succeed. Start with reusable fixture-driven conformance tests and precise preparation diagnostics. Two downstream custom nodes do not justify importing the FGA macro or forcing plant state into its Workspace lifecycle.

**Do not add automatic topological sorting simply because JFG has it.** Classic/Copper compose a short atmosphere/DM/pupil/WFS/detector graph; GPI2 explicitly lists command routing, atmospheric input, three mirror/tilt branches and their OPD compositions (`GPI2Sim/src/graphs.jl:205`). AOS already checks formats, duplicate destinations, missing inputs, and ordered links (`preparation.jl:694`, `:710`; `definitions.jl:175`). No ordering failure or maintenance burden was demonstrated. Existing explicit grouped execution could be assessed separately if measured work overlap warrants it; topological sorting is not itself a parallel scheduler.

**Keep JFG joins, conditional publication, per-node commitment, live property replacement, and host-staged pipelines outside the plant by default.** These instruments expose complete-frame, same-sequence HIL exchanges. AOS validates the whole host command before mutating the target input and requires its response before the next frame (`AOS/src/algorithm_graphs/hil_boundary.jl:214`, `:270`). Classic explicitly documents startup-only configuration and rebuild (`REVOLTClassicSim/src/graphs.jl:263`). Importing different rejection/partial-commit/rate semantics would change plant evolution and RNG/model-time behavior. No downstream requirement justifies that change. RTC routing and transport already have separate owners, as required by all inspected AGENTS.md files.

## Acceptance and confidence

Source evidence is high-confidence for the GPI2 capture barrier, concrete-owner coupling, default stream selection, and diagnostic limitation. No runtime failure, hardware lifetime defect, faster execution, or instrument scientific deficiency is claimed. The primary agent owns performance experiments; the independent science review owns physical/numerical adequacy.

Implement only a separately accepted narrow change. Validate in the owning instrument and AOS/HIL package, then release and update the registered dependency bounds. Do not point the application environments at an unreleased AOS checkout or make this workspace an umbrella runtime dependency.
