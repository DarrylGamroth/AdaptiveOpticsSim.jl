## Genuine external component-oracle provenance

### OOPAO exports: genuine independent numerical references

The OOPAO bundle is materially different from the SPECULA contract bundle. Its manifest pins both `requested_ref` and `resolved_commit` to `085d5e50ace0d20fe13cc2da20129d5400166973` (`test/reference_data/manifest.toml:1–6`). The generator imports OOPAO classes, and by default clones/checks out that pinned commit; it records the actual resolved SHA in the generated manifest (`scripts/generate_oopao_reference_bundle.py:1–7, 19–20, 44–60, 63–78, 1547–1552`). The checked-in manifest has this provenance.

Representative genuine reference paths (not every bundle case is equally diagnostic):

1. **PSF** — `psf_case` constructs OOPAO Telescope/Source, calls `computePSF`, and saves `tel.PSF` (`generate_oopao_reference_bundle.py:281–310`). The manifest declares a 64×64 product generated from a 32-pixel pupil with central obstruction 0.2 and padding factor 2 (`test/reference_data/manifest.toml:8–28`). This is a component-level PSF comparison.
2. **Shack–Hartmann geometric and diffractive** — geometric ramp exports `wfs.signal_2D` from a 4×4-lenslet OOPAO SH (`:313–356`); diffractive ramp likewise exports OOPAO `signal_2D` with an explicit ramp OPD (`:359–407`). Manifest products are flattened 32-value slopes, with `atol/rtol` 1e-12 for geometric and 2e-4 / 1e-2 for diffractive (`manifest.toml:30–60, 96–127`). These establish small component parity for the declared OOPAO comparison conventions.
3. **Pyramid within the GSC branch** — the OOPAO generator exports a pyramid modulation frame and associated optical gains for a branch-step scenario (`generate_oopao_reference_bundle.py:824–...`, output cases assembled at `:1537–1546`; manifest records `kind = "pyramid_frame"`, frame parameters and branch inputs at `test/reference_data/manifest.toml:396–434`). This is an independently generated OOPAO Pyramid component product, but it is embedded in a small GSC branch scenario, not a generic Copper detector frame. A separate `pyramid_case` ramp exporter exists in the generator (`:410–464`), and matching `pyramid_diffractive_*.txt` files exist, but the current committed manifest has no `pyramid_diffractive_*` case entries. Those files therefore are not currently exercised as maintained bundle cases.
4. **LiFT interaction matrix** — `lift_case` calls OOPAO `LiFT.generateLIFTinteractionMatrices` with the OOPAO `Detector` (read noise enabled; photon noise disabled), saves a 48×48×4 stack (`:1003–1055`; manifest `:319–356`). This is the strongest checked-in detector-adjacent external product found, but it tests OOPAO's LiFT image/model matrix, not the AOS EMCCD/EM gain/noise chain.

Atmosphere coverage exists as part of OOPAO gain-sensing-camera and bounded atmosphere replay traces: `make_atmosphere` explicitly initializes OOPAO atmosphere and a seeded phase screen (`:106–118`), and these functions use that object (`:824–...`, `:1272–...`). They remain narrow GSC/replay path products with OOPAO's own atmosphere generation and scenario, rather than a full independent atmospheric propagation validation across AOS's atmospheric model family. OOPAO bundle limitations overall: small 24/32-pixel pupils, 4×4 sensors/few modes, mostly deterministic synthetic OPDs; generic OOPAO pyramid ramp arrays are not wired into the current manifest; no production instrument registration/calibration; no REVOLT/GPI instrument compositions; and no Copper EMCCD detector qualification.

The AOS reference regression invokes local case validation against the frozen OOPAO arrays (`test/testsets/reference_and_tutorials.jl:196–218`). The generator has an escape hatch to use a local OOPAO checkout, in which case it stores `local-checkout` plus the resolved SHA; the committed bundle is pinned to the exact SHA above. That makes these genuine independent generated exports, while the consuming regression itself only checks AOS against the frozen result.
